# Hybrid Portfolio Case Study Template

Gunakan template ini sebagai kontrak output. Ganti placeholder dengan fakta project dan hapus bagian
yang tidak relevan. Jangan mempertahankan placeholder pada hasil final.

```md
# [Project Title]: [High-Level Value Proposition]

## In a nutshell

[Context / Background, Problem, Users, Business / Operational Impact, Solution, Your Role, Goal,
and Result / Outcome. Convert the verified information into 2 to 3 short paragraphs explaining
the product or industry context, why the problem matters, and the goal of the project. Keep claims
grounded in available evidence. When data is missing, state expected impact or unknown instead of
inventing results.]

[Live Demo] | [IA / Architecture Diagram] | [Figma / API Documentation] | [Repository]

## Project Snapshot

- Role: [role]
- Duration: [duration]
- Scope: [scope]
- Tech Stack: [technologies]
- Project Type: [client / work / thesis / self-directed practice]

## The Problem

[2–4 sentences: user or team, pain point, bottleneck, constraint,
and why this project needed to exist.]

## Approach & Architecture

### Information Architecture

[Sitemap, navigation hierarchy, content model, or Mermaid diagram.]

### UX Writing Approach

| Context | Before | After | Reasoning |
|---|---|---|---|
| [context] | [old copy] | [new copy] | [why it changed] |

### Tech Stack

- [technology]: [role in the solution]

### Key Decisions & Trade-offs

- **[Decision]:** [why this option was chosen over the alternative]
- **[Decision]:** [constraint, trade-off, or consequence]
- **What I’d change today:** [reflection]

## Results & Performance Benchmarks

### Time Saved

- Manual baseline: [X minutes per process]
- Digital process: [Y minutes per process]
- Time saved: [X − Y minutes]
- Time saved (%): [(X − Y) / X × 100]
- Evidence status: [Measured / Estimated / Proxy / Qualitative]

### Error Reduction

- Manual error or rework rate: [X]
- Digital error or rework rate: [Y]
- Error reduction (%): [(X − Y) / X × 100]
- Evidence status: [Measured / Estimated / Proxy / Qualitative]

### Measurement Notes

[Source, sample, observation/interview method, assumptions,
frequency, and limitations.]

## Code & Artifact Deep Dive

- [IA Diagram](link): [what the artifact proves]
- [Figma Flow](link): [what the artifact proves]
- [Component / Route](link): [what the implementation proves]
- [Repository Code](link): [what the code proves]
- [Test / Validation](link): [what was checked]

## Impact

[One concise statement connecting the change to user, team,
or operational value. Label it as estimated when appropriate.]

## What I’d Change Today

[Honest limitation and next iteration.]

## Recruiter Summary

### [Project Name]

[One-line pitch]

**Problem:** [2–4 sentences]

**Architecture & decisions:**
- [Decision 1 and why]
- [Decision 2 and why]
- [What you’d change today]

**Impact:** [Concrete measured result, estimated result, proxy,
or qualitative change with its evidence status]

**Live demo:** [link]
**Repository:** [link, or note on visibility]
```

## Evidence wording

Pilih wording berdasarkan status data:

| Status | Wording yang sesuai |
|---|---|
| Measured | “Measured across 15 transactions…” |
| Estimated | “Estimated from workflow breakdown…” |
| Proxy | “Reduced the workflow from 7 steps to 3…” |
| Qualitative | “Centralized the workflow and removed duplicate manual handoffs…” |

Hindari klaim seperti “meningkatkan produktivitas 87,5%” jika angka tersebut hanya berasal dari asumsi.
Tulis “estimated 87,5% reduction in processing time” dan jelaskan metode estimasinya.
